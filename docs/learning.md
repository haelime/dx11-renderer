# 배워야 할 것

각 항목은 **보지 않고 말로 설명할 수 있으면** 체크한다. 코드가 돌아가는 것만으로는 체크하지 않는다.
면접 질문 예시는 스스로 답해보는 용도.

## 0. 공통 C++ (진행하면서 계속)

- [ ] RAII와 `Microsoft::WRL::ComPtr`가 COM 객체 수명을 어떻게 관리하는지
- [ ] `unique_ptr` / `shared_ptr` / `weak_ptr`, 이동 의미론(`std::move`)
- [ ] 가상 함수, vptr/vtable, 순수 가상 함수, 가상 소멸자가 필요한 이유
- [ ] `const` 정확성, 참조와 포인터의 차이
- [ ] 헤더/소스 분리, 전방 선언, 컴파일·링크 과정
- [ ] 디버거로 브레이크포인트, 콜스택, 조사식 쓰기

면접 질문: "ComPtr을 쓰지 않으면 어떤 문제가 생기나요?"

## 0단계: 기초 → 건너뜀 (2026-10-12)

## 1단계: 렌더러 기본

### 1-0. 빌드 기초 (창 만들면서 같이)
- [ ] 솔루션 / 프로젝트 / 필터의 차이, 프로젝트 파일이 소스 경로를 기억하는 방식
- [ ] exe와 정적 lib, 프로젝트 참조, 링크는 어디서 일어나나
- [ ] 하위 시스템(콘솔/창)과 진입점(`main` / `wWinMain`)
- [ ] 컴파일 에러(C…)와 링크 에러(LNK…) 구분하기

### 1-1. 창과 디바이스
- [ ] Win32 창 만들기, 메시지 루프 (`PeekMessage` 기반 게임 루프)
- [ ] 핸들(`HINSTANCE`, `HWND`), Windows 메시지 모델 (메시지 큐 → `WndProc`)
- [ ] `D3D11CreateDeviceAndSwapChain`: Device와 DeviceContext의 역할 차이
- [ ] 스왑체인, 백버퍼, Present, 더블 버퍼링
- [ ] 렌더 타깃 뷰, 뷰포트, 화면 지우기
- [ ] 디버그 레이어 켜기 (`D3D11_CREATE_DEVICE_DEBUG`)와 출력 창 경고 읽기

**마일스톤**: 창이 뜨고 단색으로 지워진다.

### 1-2. 첫 삼각형 = 렌더링 파이프라인
- [ ] 정점 버퍼, 입력 레이아웃(Input Layout)
- [ ] 버텍스 셰이더 / 픽셀 셰이더 (HLSL), 셰이더 컴파일
- [ ] 입력 조립 → VS → 래스터라이저 → PS → 출력 병합, 각 단계에서 내 코드가 무엇을 하는지
- [ ] 인덱스 버퍼

**마일스톤**: 삼각형, 그다음 인덱스 버퍼로 사각형.

### 1-3. 3D와 카메라
- [ ] 구조체 정렬·패딩, `sizeof`/`alignof` (상수 버퍼 구조체를 만들 때)
- [ ] 상수 버퍼, 16바이트 정렬 규칙
- [ ] 벡터, 내적, 외적
- [ ] 월드·뷰·투영 행렬 (DirectXMath), 행 우선/열 우선과 전치
- [ ] 깊이 버퍼, 깊이 스텐실 뷰, 깊이 테스트
- [ ] FPS 카메라: 마우스·키보드 입력, 외적으로 right/up 벡터 구하기
- [ ] 델타 타임

**마일스톤**: 회전하는 큐브를 카메라로 돌아다니며 본다.

### 1-4. 모델과 텍스처
- [ ] OBJ 파서 직접 작성 (miniRT 파싱 경험 활용)
- [ ] 텍스처 불러오기 (stb_image 등), 셰이더 리소스 뷰, 샘플러 상태
- [ ] UV 좌표, 밉맵 개념

**마일스톤**: 텍스처 입힌 모델 하나.

### 1-5. 조명
- [ ] 법선과 법선 변환(역전치 행렬이 필요한 이유)
- [ ] Phong / Blinn-Phong: 환경광, 확산광(내적), 정반사광
- [ ] 방향광, 점광원

**마일스톤**: 조명이 움직이면 음영이 바뀐다.

### 1-6. (여유 있으면) 그림자 맵
- [ ] 빛 시점에서 깊이 렌더링, 두 번째 패스에서 비교
- [ ] 섀도 아크네, 바이어스

**1단계 완료 기준**

## 2단계: 멀티스레드 (에셋 비동기 로딩)

## C#은 어떻게 할까

새 프로젝트를 하나 더 시작하지 않는다. 대신:
- **C++ 렌더러가 메인**(평일). 이스트게임즈(카발)가 C++이기 때문.
- **C#은 Unity 창작으로**(주말, 잼). 이미 실무 수준으로 아는 영역이라 감을 유지하는 정도면 된다. 잼 게임도 이제 **직접 짠 코드**로.
- **3단계 이후 선택 과제**: C#(.NET 소켓)으로 서버에 접속하는 **테스트 봇**을 만든다. 같은 패킷 구조를 C#으로 직렬화해야 해서 두 언어를 모두 보여줄 수 있고, 서버 부하 테스트도 된다.
- 면접 대비 C# 이론(값/참조 타입, 박싱, GC, 코루틴)은 이미 강하니 주 1회 복습만.
- 코딩 테스트는 **C++ 하나로** 통일.
